## 1. 测试概述

本报告基于项目现有 pytest 测试代码，覆盖后端核心业务逻辑和 API 接口。测试重点包括：

- 划价计算与库存扣减单元测试；
- 挂号、收费、发药核心业务流程；
- 号源耗尽、库存不足、重复收费、重复发药等边界场景；
- 登录认证、JWT、RBAC 越权访问；
- 审计日志、药品 CSV 导入、统计报表。

测试目标：

1. 验证核心业务规则正确；
2. 验证关键异常分支会正确回滚或拒绝；
3. 验证不同角色只能访问授权接口；
4. 验证审计日志能够记录关键写操作；
5. 验证前端依赖的后端接口返回结构稳定。

## 4. 典型测试用例说明

### 4.1 划价计算正常场景

文件：

```text
tests/test_core_business_units.py::test_calculate_total_normal
```

测试内容：

- 药品 A 单价 12.50，数量 2；
- 药品 B 单价 3.20，数量 1；
- 调用 `_calculate_total`。

预期：

```text
12.50 × 2 + 3.20 × 1 = 28.20
```

验证点：

- 后端按药品档案单价计算；
- 多明细金额正确汇总；
- 使用 Decimal 避免浮点误差。

结果：PASSED

### 4.2 库存扣减边界场景

文件：

```text
tests/test_core_business_units.py::test_deduct_stock_zero_stock_raises
```

测试内容：

- 药品库存为 0；
- 调用 `deduct_stock(db, drug_id, 1)`。

预期：

- 抛出 `InsufficientStockError`；
- 库存仍为 0；
- 不出现负库存。

结果：PASSED

同时覆盖：

- 数量为 0；
- 药品不存在；
- 正常扣减后库存减少。

### 4.3 号源耗尽与回滚

文件：

```text
tests/test_core_api_flows.py::test_registration_normal_and_quota_exhausted
```

测试内容：

- 创建最大号源为 1 的排班；
- cashier 第一次挂号成功；
- 第二次挂号请求。

预期：

- 第一次返回 201，剩余号源变为 0；
- 第二次返回 400；
- 号源保持 0；
- 只生成 1 条挂号记录。

验证点：

- 号源扣减和挂号记录创建在同一事务；
- 号源为 0 时拒绝挂号；
- 不会出现负号源。

结果：PASSED

### 4.4 收费金额安全与重复收费

文件：

```text
tests/test_core_api_flows.py::test_charge_normal_and_duplicate_rejected
```

测试内容：

- 创建两项药品明细；
- 收费请求中故意传入伪造的 `total_amount` 和 `price`；
- 对同一处方重复收费。

预期：

- 后端忽略前端传入价格；
- 按药品档案单价计算总金额；
- 第一次收费返回 201；
- 第二次收费返回 409；
- 只生成一张收费单。

验证点：

- 金额计算权威在后端；
- 收费单唯一；
- 处方 `paid` 状态与收费单一致。

结果：PASSED

### 4.5 库存不足整单回滚

文件：

```text
tests/test_core_api_flows.py::test_dispense_insufficient_stock_rolls_back
```

测试内容：

- 药品库存为 1；
- 处方数量为 2；
- 先完成收费，再尝试发药。

预期：

- 发药返回 400；
- 药品库存保持 1；
- 不生成发药记录；
- 处方仍保持已收费状态。

验证点：

- 发药事务全部成功或全部回滚；
- 库存不足不会部分扣减。

结果：PASSED

多药品场景还覆盖：

```text
tests/test_drug_dispense.py::test_dispense_multi_item_rolls_back_all_stock_changes
```

验证一张处方中任一药品库存不足时，其他药品库存也不被扣减。

### 4.6 越权访问控制

文件：

```text
tests/test_core_api_flows.py::test_role_access_control
```

测试内容：

- doctor、pharmacist 调用挂号 POST；
- admin、cashier 调用挂号 POST；
- doctor、pharmacist 调用收费接口；
- cashier、doctor 调用发药接口；
- 未登录调用写接口。

预期：

- doctor、pharmacist 挂号返回 403；
- admin、cashier 挂号返回 201；
- 收费仅 cashier 成功；
- 发药仅 pharmacist 成功；
- 未登录返回 401。

验证点：

- 挂号权限为 admin/cashier；
- 收费权限为 cashier；
- 发药权限为 pharmacist；
- 前端隐藏入口之外，后端仍做强校验。

结果：PASSED
